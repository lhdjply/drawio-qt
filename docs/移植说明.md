# 移植说明：从 Electron 桌面版到原生 Qt6

本文记录把 [`jgraph/drawio-desktop`](https://github.com/jgraph/drawio-desktop)（v32.6.10）
移植为原生 Qt6 / C++ 应用时的分析结论、技术选型与模块对应关系。

## 1. 上游架构回顾

Electron 版由三部分组成：

```
drawio-desktop/
├── src/main/electron.js         主进程（约 4200 行）：窗口、菜单、文件、打印、导出、更新
├── src/main/electron-preload.js 预加载脚本：把 IPC 包装成 window.electron
├── src/main/*.js                可测试的纯逻辑模块（参数解析、窗口位置、备份、PDF/PNG 元数据等）
└── drawio/src/main/webapp/      draw.io Web 编辑器（mxGraph + 业务代码，约 100MB）
```

渲染进程（Web 编辑器）通过 `window.electron.request(action, callback, error)` 与主进程通信，
主进程在 `ipcMain.on('rendererReq')` 中分发 `saveFile`、`readFile`、`showOpenDialog`、
`watchFile` 等 20 余种操作。导出则由主进程创建隐藏 `BrowserWindow` 加载 `export3.html`，
把 `render` 消息发给渲染器，渲染器用 `render-finished` 回传画布尺寸，主进程再
`capturePage()`/`printToPDF()`/`get-svg-data` 生成文件。

## 2. 技术选型

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. WebEngine 壳 | Qt + `QWebEngineView` 加载原 webapp，用 `QWebChannel` 复刻 IPC | 功能 100% 一致、工作量小 | 仍然依赖 Chromium；打包体积大；并非“原生” |
| B. 原生重写（本项目） | C++ 重写数据模型、渲染、交互、导入导出 | 真正原生、体积小、启动快、可深度定制 | 无法覆盖 draw.io 全部特性 |

按需求选择方案 B：**不链接 Qt WebEngine，不执行 JavaScript，编辑器内核完全由 C++ 实现。**

## 3. 模块对应关系

| Electron / Web 端 | 原生实现 | 说明 |
| --- | --- | --- |
| `src/main/args.js` | `app/Args.*` | 相同的选项表、组合短参数、`--x=y`、默认值 |
| `src/main/window-bounds.js` | `AppSettings` + Qt 窗口几何 | 用 `saveGeometry()` 代替手写 lastWinSize |
| `src/main/config-paths.js` | `AppSettings` | 配置/最近文件改存 `QSettings` |
| `src/main/backup-file.js` | `Document::save` + `QSaveFile` | 原子写 + `fsync` 语义 |
| `src/main/file-watcher.js` | `QFileSystemWatcher` | 外部修改提示重载 |
| `src/main/print-options.js` | `QPrinter` + `QPageSize` | 页面尺寸按 1/100 英寸换算为毫米 |
| `src/main/png-xml.js` / `pdf-xml.js` | `core/FileMeta.*` | PNG `zTXt`、PDF `/Subject`、SVG `content` |
| `src/main/html-export.js` | `io/HtmlExport.*` | 同样输出 `data-mxgraph` + viewer 脚本 |
| `src/main/electron.js` 的窗口/菜单 | `ui/MainWindow.*` | 菜单项、快捷键、停靠面板 |
| webapp 的画布与 mxGraph | `core/Cell`、`render/*`、`ui/DiagramView` | 自绘形状、连接线与交互 |

| `electron-updater` | — | 原生版不提供自动更新 |
| `electron-store` | `QSettings` | INI 持久化 |
| `electron-context-menu` | `DiagramView::contextMenuEvent` + `QMenu` | 画布右键菜单 |
| `electron-log` | `qWarning` / 状态栏 | 简化 |

### 3.1 IPC 方法映射

Web 编辑器的 `rendererReq` 动作在原生版中不再需要 IPC，直接调用对象方法：

| IPC action | 原生 API |
| --- | --- |
| `saveFile` | `Document::save()`（含原子写、覆盖检查） |
| `writeFile` | `QSaveFile`/`QFile` |
| `readFile` | `QFile` + `Document::load()` |
| `saveDraft` / `getFileDrafts` / `getBkpFile` | `MainWindow::writeDraft()` / 草稿恢复对话框 |
| `getDocumentsFolder` | `QStandardPaths::DocumentsLocation` |
| `checkFileExists` | `QFileInfo::exists()` |
| `showOpenDialog` / `showSaveDialog` | `QFileDialog` |
| `dirname` | `QFileInfo::absolutePath()` |
| `fileStat` / `isFileWritable` | `QFileInfo` / `QFile::isWritable()` |
| `clipboardAction` | `QClipboard` / `DiagramView` 内部剪贴板 |
| `deleteFile` | `QFile::remove()` |
| `windowAction` | `MainWindow::close()/setWindowState()` |
| `openExternal` | `QDesktopServices::openUrl()`（当前版本未暴露超链接点击） |
| `watchFile` / `unwatchFile` | `QFileSystemWatcher` |
| `exit` | `QApplication::closeAllWindows()` |
| `getLocalFonts` / `isFullscreen` / `getUpdateState` | 不适用（Qt 字体库、`isFullScreen()`） |
| `export` | `Exporter::exportDocument()` |

## 4. `.drawio` 文件格式实现

### 4.1 容器

```xml
<mxfile host="drawio-qt" agent="drawio-qt/1.0.0" version="32.6.10" type="device">
  <diagram id="..." name="第 1 页">…页面内容…</diagram>
</mxfile>
```

页面内容有两种形式：

1. **未压缩**：直接内嵌 `<mxGraphModel>`；
2. **压缩**：`base64(deflateRaw(encodeURIComponent(xml)))` 文本。

`Compression::compressDiagram` / `decompressDiagram` 精确复刻 `Graph.compress` 的行为：

- `encodeURIComponent` 的保留字符集：`A-Z a-z 0-9 - _ . ! ~ * ' ( )`；
- 使用 zlib 的 **raw deflate**（`windowBits = -15`），不是 gzip/zlib 容器；
- base64 使用标准字母表。

### 4.2 单元与层级

- `mxCell` 的 `vertex="1"` / `edge="1"` 分别对应 `Cell::Kind::Vertex/Edge`；
- `parent="0"` 且不是顶点/边的是**图层**，由 `Page::layers` 表示；
- 其余单元格的 `parentId` 指向图层或分组；分组是带子元素的顶点；
- 子元素坐标相对于父元素，`Cell::absoluteRect()` 递归换算。

### 4.3 内嵌图数据

| 格式 | 位置 | 编码 |
| --- | --- | --- |
| PNG | `zTXt` 块，关键字 `mxGraphModel` | zlib 压缩 `percentEncode(xml)`，与上游 `writePngWithText` 相同 |
| PDF | Info 字典 `/Subject` | PDF 字面字符串 `(%3Cmxfile…)`，通过增量更新写入 |
| SVG | 根元素 `content` 属性 | `percentEncode(xml)` |

PDF 的写入方式说明：Qt 的 `QPdfWriter` 只支持标题/创建者等有限元数据，
因此 `FileMeta::embedXmlInPdf` 在文件末尾追加一个**增量更新段**（新的 Info 对象 + 新 xref +
`/Prev` 指向旧 xref），保持原 PDF 内容与阅读器兼容性。读取时同时支持字面字符串与十六进制
字符串（兼容 draw.io 的 `pdf-lib` 输出），并在必要时把压缩载荷解压。

## 5. 命令行参数

`app/Args.cpp` 复刻了 `args.js` 的解析行为（含 `-xa` 组合、`-fpng` 附加值、`--` 终止符、
非法值回退默认），支持的核心参数：

`-c/-k/-x/-r/--timeout/-o/-f/--layout/--normalize/--mermaid-image/-q/-t/-e/--embed-svg-*/-b/-s/
--width/--height/--crop/--size/-a/-p/-l/-g/-u/-z/--theme/--svg-theme/--svg-links-target/--html-*`

其中依赖 Web 编辑器的 `--layout`、`--normalize`、`--mermaid-image` 会被接受但给出“尚未实现”提示；
其余参数在原生导出管线中生效。`-V/--version`、`-h/--help` 的行为与上游一致。

## 6. 交互与渲染的差异

| 能力 | Electron（Web 编辑器） | 原生版 |
| --- | --- | --- |
| 形状库 | 数百种 stencil + 自定义 | 23 种基础形状，可通过 `ShapeRegistry` 扩展 |
| 连接点 | 悬停形状显示方向箭头，拖拽生成 | 相同（悬停显示 4 个连接点，或按 C 使用连线工具、Ctrl+拖动） |
| 文本 | contenteditable + 完整 HTML/CSS | `QTextEdit` 覆盖层 + 简化 HTML（`<b>/<i>/<u>/<br>/<font>`） |
| 数学公式 / Mermaid | MathJax / Mermaid 渲染 | 不支持 |
| 路由 | mxGraph 完整路由器（含避障） | 曼哈顿路由 + 控制点，无避障 |
| 撤销 | mxUndoManager 细粒度命令 | 页面快照（200 步） |
| 页面/图层 | 完整 UI | 多页面完整 UI；图层可读写但无管理面板 |
| 打印 | Chromium 打印管线 | `QPrinter` / `QPrintPreviewDialog` |
| 自动更新 | electron-updater | 无 |

## 7. 安全与健壮性

- 文件写入统一使用 `QSaveFile`（临时文件 + 原子重命名），避免半写损坏；
- 批量导出时跳过符号链接，防止目录扫描越界（对应上游 GHSA-2w35-fgjm-2vvh 的修复思路）；
- `--check` 输出冲突时生成 `name-1.ext` 而不是覆盖；
- 草稿写入用户数据目录（`QStandardPaths::AppDataLocation`），恢复前比较修改时间；
- 不执行任何来自文件的脚本/HTML：HTML 标签只按白名单子集渲染，避免脚本注入；
- 解析 XML 使用 `QDomDocument`/`QXmlStreamReader`，不加载外部实体。

## 8. 后续可扩展方向

1. 图层管理面板（数据层已支持 `Layer{id,name,visible,locked}`）；
2. 自定义 stencil（解析 draw.io 的 `<shape>` 描述或 SVG）；
3. 连接点吸附与智能参考线；
4. 更多导出选项（SVG 多页面视图、PDF 注释/链接）；
5. 使用 `QPainterPath` 与空间索引优化超大文档；
6. 通过 `QDesktopServices` 支持超链接与 `openExternal`。
